# TSIPPOLibrary (API)

Серверное REST-приложение для управления библиотекой без фронтенда.

__Технологический стек:__
- **Java 27**, **Spring Boot 3.x**
- **Spring Web** - RESR API
- **Spring Security + JWT** - аутентификация и авторизация
- **Spring Data Jpa (Hibernate)** - доступ к БД
- **PostgreSQL** - СУБД
- **Redis** - кэширование
- **Spring Sсheduler** - планировщик

__Роли и возможности:__
Гость - регистрация и вход
Пользователь - просмотр каталога книг, бронирование и возврат книги, росмотр и редактирвание своих данных
Администратор - управление книгами и пользователями (кроме других администраторов и владельца) + возможности пользователя
Владелец - имеет полный доступ: управляет любыми учётными записями, назначает администраторов

__Аутентификация:__
- **access token** (JWT в течении 30 минут) передаётся в заголовке 'Authrization'
- **refresh token** (30 дней) храниться в БД в виде хэша и используется тоько для обновления access токена

Запрос без токена или с недействительным токеном ведёт к коду 401 (Unauthorized)
Запрос без нужных прав (роли) ведёт к коду 403 (Forbidden)

__Основные эндпоинты:__ <br>
POST /api/auth/register - регистрация <br>
POST /api/auth/login - авторизация + аутентификация <br>
POST /api/auth/logout - выход из аккаунта (удаление токенов) <br>
<br>
GET /api/books - получение каталога книг (пагинация и сортировка по желению пользователя)<br>
GET /api/books/{id} - получение конкретной книги<br>
POST /api/books [ADMIN, OWNER] - добавление книги<br>
PUT /api/books/{id} [ADMIN, OWNER] - обновление конкретной книги<br>
DELETE /api/books/{id} [ADMIN, OWNER] - удаление книги<br>
<br>
POST /api/assign - бронирование книги<br>
POST /api/assigns/{id}/release - возврат книги<br>
GET /api/assigns - пользователь просматривает список свох забронированных книг<br>
GET /api/assigns/all [ADMIN, OWNER] - просмотр всех забронированных книг<br>
<br>
GET /api/profile - просмотр собственного профиля<br>
GET /api/users [ADMIN, OWNER] - список всех пользователей<br>
GET /api/users/{id} [ADMIN, OWNER] - получение конкретного пользователя<br>
DELETE /api/users/{id} [ADMIN, OWNER] - удаление пользователя<br>
PATCH /api/users/{id}/role [OWNER] - назначение администратора<br>
<br>
__Особенности реализации:__
- Бронировние уменьшает количество доступных экземпляров книг, а возврат увеличивает
- Лимит активных бронирований у одного пользователя - 5 книг
- Кэш каталога книг в Redis, инвалидация при изменении/удалении книги, полная очистка каждую ночь в 00 00
- Документация API - OpenAPI/Swagger UI
